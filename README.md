# Синхронизация Google Spreadsheet с базой данных

Небольшая программа на Python, которая читает таблицу с бронированиями и
сохраняет данные в SQLite. При повторном запуске записи не дублируются.

## Запуск

Нужен Python 3.11 или новее.

```bash
python -m booking_sync \
  --sheet-url "https://docs.google.com/spreadsheets/d/1vKtaExZRjQcxuyNwvXK4NslFQoFFpfKKXh24o9dHHvM/edit#gid=0" \
  --database data/bookings.db \
  --allow-errors
```

Таблица должна открываться по ссылке на чтение. Также можно использовать заранее
скачанный CSV-файл:

```bash
python -m booking_sync --csv-file source.csv --database data/bookings.db --allow-errors
```

После запуска программа выводит простой отчёт:

```json
{
  "rows_read": 10,
  "blank_rows": 1,
  "valid_records": 6,
  "invalid_rows": 2,
  "duplicate_rows": 1,
  "conflicts": 0,
  "inserted": 6,
  "updated": 0,
  "unchanged": 0,
  "stale": 0
}
```

На выданной в задании таблице программа читает 38 строк: 1 пустую строку
пропускает, получает 27 корректных записей, 9 строк с ошибками и 1 повторный
`record_id`. Повторный запуск не создаёт новые записи.

Если есть некорректные строки или конфликт версий, программа возвращает код `2`.
Параметр `--allow-errors` разрешает частичный результат и возвращает код `0`.

## Как работает программа

1. Ссылка Google Spreadsheet преобразуется в ссылку для выгрузки CSV.
2. Программа проверяет, что нужные колонки присутствуют.
3. `record_id` очищается и приводится к верхнему регистру.
4. Для повторяющихся `record_id` сначала выбирается самая новая версия.
5. Выбранная версия проверяется, после чего сохраняется в `bookings`.
6. Ошибки сохраняются в `sync_errors` без имени, телефона и примечания гостя.

## Какие решения я принял

- В базе есть обычный числовой `id`. Поле `record_id` из таблицы хранится отдельно
  как уникальное и используется для синхронизации.
- Одинаковые имя гостя, телефон или объект не считаю дублем: у гостя может быть
  несколько бронирований.
- Если один `record_id` встречается несколько раз, беру строку с более новым
  `updated_at`.
- Если запись уже есть в базе, обновляю её только при более новом `updated_at`.
- Если время одинаковое, но данные отличаются, записываю конфликт и не изменяю
  базу. Для сравнения данных используется SHA-256.
- Если самая новая версия содержит ошибку, старую версию вместо неё не загружаю.
- Записи, которых больше нет в таблице, автоматически не удаляю. Это защищает от
  случайного удаления данных.
- Сумма хранится целым количеством филсов, чтобы не использовать `float` для
  денежных значений.
- Телефон и примечание могут быть пустыми. Остальные основные поля обязательны.
- Неизвестный канал сохраняю как есть, потому что в будущем могут появиться новые
  источники бронирований.

В базе создаются две таблицы:

- `bookings` — загруженные бронирования;
- `sync_errors` — ошибки последнего запуска с номером строки и `record_id`.

## Проверка

```bash
python -m unittest discover -v
```

Тесты проверяют преобразование ссылки, телефон, дубли, регистр `record_id`,
невалидную новую версию, конфликт одинакового времени, обычное обновление,
устаревшую версию и повторный запуск без создания новых записей.

Если развивать проект дальше, можно добавить авторизацию через Google API,
PostgreSQL вместо SQLite и запуск по расписанию.
